## What nkr is

nkr is a Nostr relay written in Rust. It has two deployment targets built from one protocol core:

- **Native server** (`nkr` binary): LMDB storage, a multi-threaded runtime, and the operational features of strfry. The goal is to match or beat strfry on throughput, tail latency, memory per connection, and long-running stability on the same hardware with the same durability guarantees.
- **Cloudflare Workers** (`nkr-worker`): the same protocol core compiled to `wasm32-unknown-unknown`, running in a Durable Object with its embedded SQLite. It provides identical protocol semantics and defaults. Its scale envelope is set by the platform (one thread and 10 GB per Durable Object), not by strfry.

The name is deliberately short and opaque, in the tradition of strfry and khatru. It is not an acronym.

## Goals

- **Strict protocol conformance.** nkr is the authority that enforces NIP-01 for its clients. Every rule that NIP-01 states as MUST is enforced: an empty list matches nothing, hex is lowercase and exact length, messages have fixed arity, subscription ids are 1 to 64 characters, and `OK`/`CLOSED` messages carry standard prefixes.
- **strfry parity.** strfry is the de facto reference relay. nkr adopts its defaults, its durability rule (no `OK` before the commit is durable), its write-policy plugin protocol, its Prometheus metric names, and its CLI verbs. Deliberate deviations are listed in [Compatibility](/compatibility).
- **One core, two runtimes.** All protocol decisions live in the sans-IO `nkr` crate. The runtimes only execute the commands it emits.
- **Bounded resources everywhere.** Every queue, buffer, scan, and subscription set has a limit, and every limit can be configured.

## Non-goals

- nkr is not a client SDK. Clients should use rust-nostr or `@qntx/nostr`.
- nkr has no external database backends (Postgres, MySQL). Storage is embedded: LMDB natively, Durable Object SQLite on Workers.
- The Cloudflare edition does not claim strfry-scale throughput or capacity. [Workers deployment](/architecture/workers) states its limits.

## Status

Pre-alpha. The system grows in layers. Each layer ships a relay that works end to end. Layer 1 is the NIP-01 and NIP-11 relay on the native server. See [Roadmap](/roadmap).
