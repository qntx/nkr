## Scope

The `nkr` crate implements every protocol decision a relay makes. It is target-neutral, has no unsafe code, and is driven entirely by its caller. It builds on established primitives: serde_json, secp256k1 (libsecp256k1, the library strfry uses), sha2, faster-hex, and foldhash. It does not depend on rust-nostr. [ADR 0001](/decisions/0001-strict-protocol-layer) explains why.

## Event ingest

Ingest has two stages, so that cheap rejections happen before expensive ones.

1. **Parse.** The parser borrows from the input wherever possible and checks structure and size:
   - all seven fields are present, and duplicate keys are rejected;
   - unknown fields are ignored, and they never reach storage;
   - `id` and `pubkey` are exactly 64 lowercase hex characters, and `sig` is exactly 128;
   - `kind` is an integer from 0 to 65535, and `created_at` is an unsigned integer (float spellings are rejected);
   - every tag is a non-empty array of strings;
   - limits on tag count and tag value size are enforced;
   - the first value of every `e` and `p` tag must be 64 lowercase hex (the strfry rule).
2. **Policy checks.** The session checks the time window against the injected clock. By default it rejects events more than 900 seconds in the future, more than three years old, or ephemeral events older than 60 seconds.
3. **Verify.** Hash the NIP-01 preimage, compare the result with the claimed id, and verify the BIP-340 signature over the id. Then build the canonical JSON, enforce the maximum event size on it, and build the packed record.

The id preimage is serialized with serde_json. Its escaping is identical to `JSON.stringify`, which is the encoding the ecosystem actually hashes. The shared vector set confirms this (nostr-tools agrees on every case).

### Canonical JSON

Stored and served form: keys in NIP-01 order (`id`, `pubkey`, `created_at`, `kind`, `tags`, `content`, `sig`), no whitespace, serde_json string escaping. It is produced once per event and inserted verbatim into every `EVENT` frame.

## Packed record

A compact, fixed-layout summary of the indexable fields. It is what the filter matcher reads, both from the LMDB memory map (zero copy) and from memory in the live index. One matcher serves both paths, so historical and live matching cannot disagree.

| Offset | Size     | Field                                              |
| ------ | -------- | -------------------------------------------------- |
| 0      | 32       | event id                                           |
| 32     | 32       | pubkey                                             |
| 64     | 8        | `created_at`, little endian                        |
| 72     | 2        | kind, little endian                                |
| 74     | 8        | NIP-40 expiration, 0 when absent                   |
| 82     | variable | tag entries: name (1 byte), length (1 byte), value |

Tag indexing rule, the same as strfry:

- Only tags whose name is a single ASCII letter are indexed, and only their first value.
- `e` and `p` values are stored as their 32 raw bytes. Every other value is stored as its UTF-8 bytes.
- Values longer than 255 bytes are not indexed. A filter on such a value never matches, in scans and live alike.

## Filters

Filters are strict NIP-01:

- Accepted keys: `ids`, `authors`, `kinds`, `since`, `until`, `limit`, and single-letter tag keys (`#e`, `#t`, and so on). Any other key, including `search`, is rejected with `unsupported:`.
- `ids`, `authors`, `#e`, and `#p` hold exact 64-character lowercase hex. Prefix matching was removed from NIP-01 and is not supported.
- An empty list makes the filter impossible: it matches nothing and the store skips it. It is never treated as an absent condition.
- Lists are compiled into sorted, deduplicated arrays. Matching uses binary search and never allocates.
- `limit` applies to the initial query only. The effective limit is the minimum of the requested limit and the configured maximum (500 by default). It is further capped where the filter bounds the result: the number of ids, or authors times kinds when every kind is replaceable.

## Messages

Client messages are parsed as a JSON array of raw values with exact arity per verb: `EVENT`, `REQ`, `CLOSE`, `COUNT`, `AUTH`, `NEG-OPEN`, `NEG-MSG`, `NEG-CLOSE`. Subscription ids must be 1 to 64 Unicode characters. NEG payloads must be non-empty, even-length lowercase hex.

Relay frames are assembled from pre-escaped parts. A subscription id is escaped once, when the subscription is created. Event JSON is inserted verbatim.

Reasons in `OK`, `CLOSED`, and `NEG-ERR` always start with a standard prefix: `duplicate`, `pow`, `blocked`, `rate-limited`, `invalid`, `restricted`, `mute`, `error`, `auth-required`, or `unsupported`.

## Session

One session per connection. It holds the subscription table and the limits, consumes text frames, and emits commands:

```rust
pub enum Command {
    Publish(Arc<Event>),
    Subscribe { sub: SubKey, filters: Arc<[Filter]> },
    Unsubscribe { sub_id: SubId },
    Send(String),
}
```

Each subscription has a key made of its id and a monotonically increasing generation. Replacing a subscription id emits an unsubscribe and then a subscribe with a new generation. Before sending any `EVENT` or `EOSE` frame, the runtime asks the session whether that key is still current.

## Live-subscription index

The live index works like strfry's ActiveMonitors:

- Each possible filter is indexed under exactly one field, chosen in this priority: ids, then authors, then the tag key with the fewest values, then kinds. Filters with none of these go on a match-all list.
- An incoming event looks up its id, pubkey, each packed tag, its kind, and the match-all list. Each candidate filter is then fully matched against the packed record.
- A per-call stamp makes each subscription match at most once per event, with no allocation.
- Hash maps use randomly seeded foldhash, because their keys come from clients.

The index is generic over the connection handle, so the native shards and the Durable Object use the same code.
